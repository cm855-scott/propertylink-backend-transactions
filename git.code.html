1. Prevent overlapping active leases

-- PropertyLink: Prevent a unit from having overlapping active leases

DELIMITER //

CREATE TRIGGER prevent_overlapping_active_lease
BEFORE INSERT ON leases
FOR EACH ROW
BEGIN
    IF NEW.status = 'Active' THEN

        IF EXISTS (
            SELECT 1
            FROM leases
            WHERE unit_id = NEW.unit_id
              AND status = 'Active'
              AND NEW.start_date <= end_date
              AND NEW.end_date >= start_date
        ) THEN

            SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT =
            'Cannot create lease: Unit already has an overlapping active lease';

        END IF;

    END IF;
END //

DELIMITER ;

Also protect updates:

DELIMITER //

CREATE TRIGGER prevent_overlapping_active_lease_update
BEFORE UPDATE ON leases
FOR EACH ROW
BEGIN
    IF NEW.status = 'Active' THEN

        IF EXISTS (
            SELECT 1
            FROM leases
            WHERE unit_id = NEW.unit_id
              AND lease_id <> NEW.lease_id
              AND status = 'Active'
              AND NEW.start_date <= end_date
              AND NEW.end_date >= start_date
        ) THEN

            SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT =
            'Cannot update lease: Unit already has an overlapping active lease';

        END IF;

    END IF;
END //

DELIMITER ;

2. Rent payment transaction

This is the main multi-step transaction. It records the payment and updates the tenant's outstanding balance.

DELIMITER //

CREATE PROCEDURE process_rent_payment(
    IN p_lease_id INT,
    IN p_amount DECIMAL(10,2),
    IN p_payment_date DATE,
    IN p_payment_method VARCHAR(50)
)
BEGIN

    DECLARE v_balance DECIMAL(10,2);
    DECLARE v_tenant_id INT;

    -- Roll back everything if an error occurs
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        RESIGNAL;
    END;

    START TRANSACTION;

    -- Get tenant and lock the balance row
    SELECT tenant_id, outstanding_balance
    INTO v_tenant_id, v_balance
    FROM leases
    WHERE lease_id = p_lease_id
    FOR UPDATE;

    -- Validate lease
    IF v_tenant_id IS NULL THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Lease does not exist';
    END IF;

    -- Validate payment
    IF p_amount <= 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Payment amount must be greater than zero';
    END IF;

    -- Record payment
    INSERT INTO payments
    (
        lease_id,
        tenant_id,
        amount,
        payment_date,
        payment_method
    )
    VALUES
    (
        p_lease_id,
        v_tenant_id,
        p_amount,
        p_payment_date,
        p_payment_method
    );

    -- Update outstanding balance
    UPDATE leases
    SET outstanding_balance =
        GREATEST(outstanding_balance - p_amount, 0)
    WHERE lease_id = p_lease_id;

    COMMIT;

END //

DELIMITER ;

Run it with:

CALL process_rent_payment(
    1,
    2500.00,
    '2026-09-30',
    'Mobile Money'
);

3. Stored procedure — Post rent charge

DELIMITER //

CREATE PROCEDURE post_rent_charge(
    IN p_lease_id INT,
    IN p_amount DECIMAL(10,2),
    IN p_charge_date DATE,
    IN p_description VARCHAR(255)
)
BEGIN

    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        RESIGNAL;
    END;

    START TRANSACTION;

    -- Check that the lease exists
    IF NOT EXISTS (
        SELECT 1
        FROM leases
        WHERE lease_id = p_lease_id
    ) THEN

        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Lease does not exist';

    END IF;

    -- Validate charge
    IF p_amount <= 0 THEN

        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Charge amount must be greater than zero';

    END IF;

    -- Insert rent charge
    INSERT INTO rent_charges
    (
        lease_id,
        amount,
        charge_date,
        description
    )
    VALUES
    (
        p_lease_id,
        p_amount,
        p_charge_date,
        p_description
    );

    -- Increase outstanding balance
    UPDATE leases
    SET outstanding_balance =
        outstanding_balance + p_amount
    WHERE lease_id = p_lease_id;

    COMMIT;

END //

DELIMITER ;

Example:

CALL post_rent_charge(
    1,
    2500.00,
    '2026-09-01',
    'September 2026 Rent'
);

4. Stored procedure — Calculate outstanding balance

DELIMITER //

CREATE PROCEDURE calculate_outstanding_balance(
    IN p_lease_id INT
)
BEGIN

    SELECT
        l.lease_id,
        l.tenant_id,

        COALESCE(
            (
                SELECT SUM(rc.amount)
                FROM rent_charges rc
                WHERE rc.lease_id = l.lease_id
            ),
            0
        ) AS total_charges,

        COALESCE(
            (
                SELECT SUM(p.amount)
                FROM payments p
                WHERE p.lease_id = l.lease_id
            ),
            0
        ) AS total_payments,

        COALESCE(
            (
                SELECT SUM(rc.amount)
                FROM rent_charges rc
                WHERE rc.lease_id = l.lease_id
            ),
            0
        )
        -
        COALESCE(
            (
                SELECT SUM(p.amount)
                FROM payments p
                WHERE p.lease_id = l.lease_id
            ),
            0
        ) AS outstanding_balance

    FROM leases l
    WHERE l.lease_id = p_lease_id;

END //

DELIMITER ;

Run:

CALL calculate_outstanding_balance(1);

5. Failure testing

This demonstrates that the transaction rolls back if something goes wrong.

Test invalid payment

CALL process_rent_payment(
    1,
    -500.00,
    '2026-09-30',
    'Cash'
);

Expected result:

Payment amount must be greater than zero

The transaction is rolled back, so no payment is inserted and the balance is not changed.

Test invalid lease

CALL process_rent_payment(
    99999,
    2500.00,
    '2026-09-30',
    'Cash'
);

Expected:

Lease does not exist

Again, the transaction is rolled back.

7. ACID demonstration

This part is mainly documentation rather than code, but the transaction above demonstrates it:

ATOMICITY
-----------
A rent payment consists of multiple operations.

If one operation fails, ROLLBACK
undoes all operations.

CONSISTENCY
-----------
The database cannot contain an invalid payment or
an invalid outstanding balance after the transaction.

ISOLATION
-----------
SELECT ... FOR UPDATE prevents another transaction
from changing the same lease balance while the payment
transaction is being processed.

DURABILITY
-----------
After COMMIT, the payment and balance update are
permanently saved in the database.

README.md

# PropertyLink - Business Logic & Transactions

## Business Logic & Transactions Lead

This module implements the database business rules and
transactions for the PropertyLink system.

## Implemented Features

1. Prevent overlapping active leases.
2. Process rent payments using database transactions.
3. Post rent charges.
4. Calculate outstanding balances.
5. Use COMMIT and ROLLBACK for transaction control.
6. Test transaction failure scenarios.

## Transaction Control

The rent payment transaction uses:

- START TRANSACTION
- COMMIT
- ROLLBACK
- SELECT ... FOR UPDATE

## ACID

### Atomicity
All payment operations succeed together or are rolled back.

### Consistency
Business rules prevent invalid lease and payment records.

### Isolation
Rows are locked while the payment transaction is being processed.

### Durability
Committed transactions remain saved in the database.

## Testing

Failure scenarios include:

- Invalid lease ID
- Negative payment amount
- Overlapping active lease

The transaction is rolled back whenever an error occurs.
